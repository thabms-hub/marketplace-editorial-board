เอกสารนี้อธิบายโครงสร้างเว็บทั้งสองส่วนที่เชื่อมกัน: **หน้าร้าน (Storefront)** ที่โรงพยาบาลเห็น และ **คอนโซลกองบรรณาธิการ (Editorial Console)** ที่ใช้ตรวจ จัดวาง และส่งขึ้นหน้าจริง

| หน้าร้าน (ฉบับร่าง) | `bms-marketplace-preview/BMS Marketplace.dc.html` | `storefront-standalone.html` |

## 1. แผนผังระบบ

```
โรงพยาบาล ──▶ หน้าร้าน (Storefront)
                  ▲
                  │ ส่งขึ้นจริงได้ทางเดียว: M18 พรีวิว → ยืนยัน → production
                  │
ผู้พัฒนา ──▶ Developer Portal ──(E8 สะพานผลตรวจ AI)──▶ คอนโซลกองบรรณาธิการ
                  ▲                                        │
                  └──── ผลการตรวจ / ตีกลับ / เกณฑ์ ◀────────┘
```

เจ้าของข้อมูลแยกกันชัด:
- **เกณฑ์ชั้น A (A1–A4 · รวม 31 ข้อ)** — เจ้าของคือ Developer Portal · คอนโซลอ่านและใช้เรนเดอร์ฟอร์ม แก้ไม่ได้ (ส่งได้แต่คำขอแก้) · A1 8 ข้อ · A2 6 ข้อ · A3 10 ข้อ (รวมการรองรับฐานข้อมูลทุกชนิด A3.9 และความพอร์ตได้ของ SQL A3.10) · A4 6 ข้อ
- **เกณฑ์ชั้น B (B1–B6) และเส้นแบ่งกลุ่ม 1–5** — เจ้าของคือกองบรรณาธิการ
- **ระบบ ticket** — เจ้าของคือฝ่ายสนับสนุน · คอนโซลเห็นสถิติเพื่อใช้ตัดสิน ไม่ตอบ ticket

## 3. คนและสิทธิ์ (จัดการที่คน ไม่ใช่ที่บทบาท)

หนึ่งคนถือได้หลายบทบาท ทุกเมนูและทุกรายการ **เปิดให้เห็นทั้งหมด** เมื่อกดปุ่มที่อยู่นอกบทบาทที่ถือ ระบบขึ้น popup “⛔ ไม่มีสิทธิดำเนินการ” พร้อมบอกว่าต้องเป็นบทบาทใด

| คน | บทบาทที่ถือ |
|---|---|
| คุณหัทยา ทองคงหาญ | R0 บรรณาธิการสูงสุด · R1 บรรณาธิการบริหาร |
| คุณถาวร ศรีพราว | R1.5 รองบรรณาธิการ · R3 บรรณาธิการเนื้อหา · R4 ผู้ตรวจ PDPA · R5 ผู้ตรวจเทคนิค |
| คุณพรเทพ ปวงนิยม | R2 บรรณาธิการจัดวาง · R8 ผู้ประสานงานผู้พัฒนา |
| คุณศิริวิสา เปลี่ยนม่วง | R6 ผู้ตรวจคลินิก |

| การกระทำ | บทบาทที่ทำได้ |
|---|---|
| อนุมัติเผยแพร่ · ไม่ผ่าน | R0 · R1 · R1.5 |
| ตีกลับให้แก้ · ส่งเข้าที่ประชุมกอง | ทุกสายที่ตรวจชิ้นนั้น |

## 4. เครื่องยนต์เบื้องหลัง

| รหัส | หน้าที่ |
|---|---|
| E1 | จัดระดับ T อัตโนมัติจาก 5 ปัจจัย — ใช้ค่าที่สูงสุด ไม่ใช่ค่าเฉลี่ย |

| E4 | คำนวณโควตาความเป็นธรรมสดขณะวางช่อง |
| E5 | นาฬิกา SLA ที่หักช่วงหยุดตาม `paused_periods[]` 5 รหัส |
| E7 | บันทึกการใช้อำนาจพิเศษ (special_power) |
| E8 | สะพานรับผลตรวจ AI + กติกาการเติมคำตอบล่วงหน้า |
| E9 | เฝ้าสิทธิ์เคลื่อน (drift) หลังเผยแพร่ · T3 รายเดือน · T2 รายไตรมาส · T1 รายครึ่งปี |

**กติกาที่อยู่เหนือคะแนน** — ตกชั้น A แม้ข้อเดียว = ไม่ผ่าน · T3 ที่ B3 < 14 ขึ้นกลุ่ม 1–2 ไม่ได้ · มีเหตุการณ์ความปลอดภัยใน 12 เดือน = ลดหนึ่งกลุ่ม · ผิด SLA ซ้ำ = ตัดสิทธิ์พื้นที่แนะนำ 1 ไตรมาส

**การรองรับฐานข้อมูล (A3.9–A3.10)** — ต้องติดตั้งและรันได้จริงบน MySQL 5.7/8.x · MariaDB 10.x · PostgreSQL 13+ · Firebird 2.5/3.0 · MS SQL Server 2016+ พร้อม log การเชื่อมต่อของแต่ละชนิด · คำสั่ง SQL ต้องพอร์ตได้ ไม่ผูกฟีเจอร์เฉพาะผู้ผลิตโดยไม่มีทางเลือกสำรอง · รองรับไม่ครบ = ต้องประกาศชนิดที่รองรับบนหน้าร้านและถูกจำกัดกลุ่มคุณภาพ

**กติกาการใช้ผล AI** — เติมคำตอบล่วงหน้าได้เฉพาะ A3/A4 · A1/A2 ห้ามเติมเด็ดขาด (แสดงเป็นบันทึกข้างฟอร์ม) · confidence < 0.70 ไม่เติมและนับเป็นภาระงานเต็ม · เก็บคู่ aiVerdict/humanVerdict ทุกข้อ

## 5. เส้นทางพรีวิว → ส่งขึ้นหน้าจริง (M18)

```
ขั้น 1  ดูอย่างที่ผู้ใช้เห็น
        ├─ ฉบับร่างในคอนโซล (staging) → storefront-standalone.html#draft=1&ctx=…&page=…
        └─ หน้าจริงตอนนี้ (production) → artifact URL
ขั้น 2  ตรวจรายการ + ดูส่วนต่างจากหน้าจริง (คำนวณสดจากสถานะคอนโซล)
ขั้น 3  🚀 ส่งขึ้น production — บังคับเหตุผล · สิทธิ์ R2/R1/R0 · บันทึก snapshot
```

deep link ของฉบับร่าง: `#draft=1&ctx=<new|some|anon>&page=<home|browse|detail>&sel=<addonId>&filter=<label>`
เงื่อนไขที่บล็อกการส่ง: ยังไม่กรอก “เลือกเพราะ” · ชุดคัดสรรผิดกติกา · คอนโซลยังชี้ staging

## 7. รูปแบบ UI ที่ใช้ซ้ำทั้งระบบ

- **ตาราง ไม่ใช่การ์ด** สำหรับงานกวาดตาเปรียบเทียบ · ปุ่มหลักอยู่คอลัมน์แรกของแถว
- **ช่องค้นหาอยู่ในหน้า ไม่ใช่แถบบนสุด** — คิว · ทะเบียนผลิตภัณฑ์ · ทะเบียนผู้พัฒนา · สะพานผลตรวจ AI · บันทึกกิจกรรม (ทุกช่องกรองจริง + มีตัวนับ + มีสถานะว่าง)
- **กล่องยืนยัน 3 ชนิด** — ปกติ (มีช่องเหตุผลบังคับ + พรีวิวข้อความถึงผู้พัฒนา) · ปฏิเสธสิทธิ์ (หัวข้อ “ทำไมจึงกดไม่ได้”) · ข้อมูล (หัวข้อ “รายละเอียด” ไม่มีปุ่มยกเลิก)
- **ผลการตัดสินใจเป็นสถานะบนหน้าจอ ไม่ใช่ toast** — แถบเขียว “บันทึกแล้ว: …” และไหลเข้าบันทึกกิจกรรมจริง
- **กฎที่บล็อกการกระทำอธิบายตรงจุดที่ถูกบล็อก** ไม่ซ่อนใน tooltip
- **สถานะว่างมีข้อความบอกทางออก** ทั้งในตารางและไทม์ไลน์
